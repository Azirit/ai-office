# Feature-Sliced Design (FSD)

## Что это

Архитектурная методология для frontend-проектов. Делит код на горизонтальные слои по назначению.

## Принципы

1. **Чистая архитектура слоёв.** Каждый слой имеет чёткую ответственность.
2. **Зависимости снизу вверх.** Верхние слои зависят от нижних, не наоборот.
3. **Минимум связей.** Каждый модуль зависит только от необходимого.
4. **Публичный API.** Модули общаются через индексные файлы.

---

## Слои (снизу вверх)

### shared/ (Общий)

**Что:** Общий UI-kit, API-клиенты, утилиты, константы, типы.

**Примеры:**
- UI-компоненты (Button, Input, Modal)
- API-клиент (axios/fetch обёртки)
- Утилиты (formatDate, validateEmail)
- Константы (API_URL, ROUTES)
- Типы (User, Todo, ApiResponse)

**Правила:**
- Не зависит ни от одного слоя
- Может использоваться где угодно
- Не содержит бизнес-логики

---

### entities/ (Сущности)

**Что:** Бизнес-сущности проекта.

**Примеры:**
- User (модель пользователя)
- Todo (модель задачи)
- Product (модель товара)
- Order (модель заказа)

**Правила:**
- Зависит только от `shared`
- Содержит модель данных и basic-логику
- Не содержит UI-компонентов
- Не содержит API-вызовов

---

### features/ (Фичи)

**Что:** Пользовательские действия.

**Примеры:**
- addUser / deleteUser
- addTodo / toggleTodo / deleteTodo
- addToCart / removeFromCart
- login / logout

**Правила:**
- Зависит от `entities` и `shared`
- Содержит бизнес-логику действий
- Может содержать UI (кнопки, формы)
- Не содержит страниц

---

### widgets/ (Виджеты)

**Что:** Сложные UI-блоки.

**Примеры:**
- Header (навигация + авторизация)
- Sidebar (меню + фильтры)
- TodoList (список + добавление)
- ProductCard (карточка товара)

**Правила:**
- Зависит от `features`, `entities`, `shared`
- Содержит сложную UI-логику
- Может содержать state
- Не является страницей

---

### pages/ (Страницы)

**Что:** Маршруты (экраны).

**Примеры:**
- HomePage
- TodoPage
- ProductPage
- LoginPage

**Правила:**
- Зависит от `widgets`, `features`, `entities`, `shared`
- Содержит компоновку страницы
- Не содержит бизнес-логики
- Связан с роутингом

---

### app/ (Приложение)

**Что:** Инициализация приложения.

**Примеры:**
- Provider (ThemeProvider, AuthProvider)
- Router (роутинг)
- Store (state management)
- Global styles

**Правила:**
- Точка входа приложения
- Инициализирует всё остальное
- Не содержит UI-компонентов
- Не содержит бизнес-логики

---

## Импорты

### Разрешено

```
shared → entities → features → widgets → pages → app
```

### Запрещено

```
shared ← entities ← features ← widgets ← pages ← app
```

### Примеры

✅ Правильно:
- `features/addTodo` импортирует из `entities/todo`
- `widgets/todoList` импортирует из `features/addTodo`
- `pages/todoPage` импортирует из `widgets/todoList`

❌ Неправильно:
- `shared/button` импортирует из `features/addTodo`
- `entities/todo` импортирует из `widgets/todoList`

```
    │   └── index.ts

    └── index.ts
```

---

## Когда использовать

### Да
- Большие frontend-проекты
- Командная разработка
- Долгосрочные проекты
- Проекты с сложной бизнес-логикой

### Нет
- Простые проекты (одна страница)
- Прототипы
- MVP без масштабирования
