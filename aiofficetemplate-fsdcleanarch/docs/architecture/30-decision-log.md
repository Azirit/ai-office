# Журнал решений

## Формат записи

```markdown
### [номер] Название решения

**Статус:** Принято / Отложено / Отклонено
**Дата:** YYYY-MM-DD
**Контекст:** Что произошло и почему нужно решение
**Решение:** Что решили
**Обоснование:** Почему именно так
**Последствия:** Что это значит для проекта
```

---

## Как использовать

1. Перед изменением архитектуры — проверить, есть ли уже запись
2. Если решения нет — создать запись до реализации
3. Если решение есть — следовать ему
4. Если решение устарело — обновить статус

---

## Примеры записей

### [001] Способ хранения данных

**Статус:** Принято
**Дата:** YYYY-MM-DD
**Контекст:** Нужно выбрать способ хранения данных.
**Решение:** Хранить в `useState`. Не добавлять персистентность до требования.
**Обоснование:** Минимальная сложность. Сохранение добавит сложность (localStorage, синхронизация).
**Последствия:** При обновлении страницы данные теряются.

---

### [002] Структура сущности

**Статус:** Принято
**Дата:** YYYY-MM-DD
**Контекст:** Нужно выбрать структуру данных для сущности.
**Решение:** Объект с `id: string` и полями. id через `crypto.randomUUID()`.
**Обоснование:** Строка не имеет уникального идентификатора. Индекс массива ненадёжен при удалении/сортировке.
**Последствия:** Нужно менять тип во всех местах использования.
