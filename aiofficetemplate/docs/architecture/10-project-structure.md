# Структура проекта

## Принцип

Структура определяется потребностями задачи, а не шаблоном.

## Правила

1. **Минимум файлов до объективной необходимости.** Если компонент помещается в один файл и понятен — не разбиваем.
2. **Каждый файл имеет одну ответственность.** Название файла описывает его содержимое.
3. **Группировка по логике, а не по типу.** Связанные вещи находятся рядом.

## Типичная структура React-проекта

```
src/
├── components/    # UI компоненты
├── hooks/         # Кастомные хуки
├── types/         # TypeScript типы
├── utils/         # Вспомогательные функции
└── ...
```

## Типичная структура backend-проекта

```
src/
├── controllers/   # Обработчики запросов
├── services/      # Бизнес-логика
├── models/        # Модели данных
├── utils/         # Вспомогательные функции
└── ...
```

## Когда менять структуру

- Когда файл > 200 строк и сложно читается
- Когда в одном файле несколько ответственностей
- Когда логика дублируется между компонентами

## Когда НЕ менять

- Когда компонент < 50 строк
- Когда изменение добавляет больше файлов, чем решает проблем
- Когда рефакторинг не связан с текущей задачей
