# 40. Security Rules

## Purpose

Этот документ определяет правила безопасности в проекте.

---

## Secrets

### Правило

Никогда не коммитить секреты в репозиторий.

### Что является секретами

- API ключи
- Пароли
- Токены
- SSH ключи
- Приватные ключи
- Строки подключения к БД

### Как хранить

- Использовать `.env` файлы
- Добавлять `.env` в `.gitignore`
- Использовать переменные окружения
- Использовать секреты CI/CD

### Если секрет попал в репозиторий

1. Срочно удалить из истории
2. Ротировать (заменить) секрет
3. Проверить, не был ли секрет использован
4. Уведомить команду

---

## Dependencies

### Правило

Не устанавливать зависимости без согласования.

### Процесс

1. Проверить, есть ли зависимость в проекте
2. Если нет — запросить разрешение
3. Установить только после согласования
4. Обновить lock-файл

### Проверка

- Использовать `npm audit`
- Регулярно обновлять зависимости
- Следить за уязвимостями

---

## Input Validation

### Правило

Валидировать весь пользовательский ввод.

### Где валидировать

- На клиенте (UX)
- На сервере (безопасность)
- В базе данных (целостность)

### Что проверять

- Тип данных
- Длину
- Формат
- Границы (min/max)
- Специальные символы

---

## XSS

### Правило

Защищать от XSS атак.

### Методы

- Экранировать вывод
- Использовать CSP
- Не использовать `dangerouslySetInnerHTML`
- Валидировать URL

---

## CORS

### Правило

Настроить CORS правильно.

### Рекомендации

- Указывать конкретные домены
- Не использовать `*` в production
- Ограничивать методы и заголовки

---

## Authentication

### Правило

Не хранить пароли в открытом виде.

### Методы

- Хешировать пароли
- Использовать bcrypt/argon2
- Использовать JWT/сессии
- Реализовать logout

---

## Authorization

### Правило

Проверять права доступа на сервере.

### Уровни

- Гость
- Пользователь
- Администратор

### Где проверять

- API endpoints
- База данных (RLS)
- Клиент (только UX)

---

## Logging

### Правило

Не логировать секреты.

### Что логировать

- Действия пользователя
- Ошибки
- Время выполнения

### Что НЕ логировать

- Пароли
- Токены
- API ключи
- Персональные данные (PII)

---

## HTTPS

### Правило

Использовать HTTPS в production.

### Исключения

- localhost для разработки
- Внутренние сети (если согласовано)

---

## Headers

### Рекомендуемые заголовки

```
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
X-XSS-Protection: 1; mode=block
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

---

## Rate Limiting

### Рекомендация

Ограничивать количество запросов.

### Где применять

- API endpoints
- Формы авторизации
- Публичные API

---

## Data Encryption

### Правило

Шифровать конфиденциальные данные.

### Методы

- TLS для передачи
- AES для хранения
- Не хранить в localStorage (если не необходимо)
